KStick SMS Gateway

Send SMS to Indian mobile numbers through an API.

Send a test message


  
The API key is only sent with this request; it is not stored by this page.






  
API

  
POST /api/v1/sms

  
Authenticate with Authorization: Bearer <API key> (or X-API-Key). Send JSON or a form body:

  

    
FieldRequiredDescription

    
toyes10-digit Indian mobile number, digits only, starting with 6–9 (no +91 or 0). Sent as +91XXXXXXXXXX.

    
messagenoText to send. If omitted or empty, the gateway's configured default message is sent.

  

  
curl -X POST https://sms.example.com/api/v1/sms \
  -H "Authorization: Bearer $SMSGW_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to":"9876543210","message":"Your code is 123456"}'

  
Never send twice: Idempotency-Key

  
Add a header Idempotency-Key: <unique id> (1–100 letters, digits, . _ : -; a UUID or your
    order id works). If the request is repeated with the same key (a network timeout, a retry by your HTTP client), the gateway
    returns the first message's result instead of sending again (Idempotent-Replayed: true). Only a message that
    definitely was not sent ("status":"failed") is tried again. Reusing a key for a different number or text gives
    422. Keys are remembered per API key, permanently.

  
curl -X POST https://sms.example.com/api/v1/sms \
  -H "Authorization: Bearer $SMSGW_KEY" -H "Idempotency-Key: order-58213-otp" \
  -H "Content-Type: application/json" -d '{"to":"9876543210","message":"Your code is 123456"}'

  
Waiting

  
The request waits for the modem up to ?wait= seconds (0–90, default 60). If the SMS has not gone out by then
    (the modem is busy or slow) the answer is 202 with "status":"queued" or "sending":
    it is still sent, and status_url tells you where to check.

  
Answers (all include id, status and status_url):

  

    
StatusBodyMeaning

    
200"ok":true,"status":"sent"The network accepted the SMS

    
202"ok":true,"status":"queued" / "sending"Still going; poll GET /api/v1/sms/{id}

    
503"ok":false,"status":"failed"Not sent (modem not registered, network refused): safe to retry

    
503"ok":false,"status":"unknown"The modem did not answer in time: it may have been sent. A retry with the same Idempotency-Key will not send it again

  

  
{"ok":true,"id":"3f1c…","status":"sent","to":"+919876543210","message_source":"request","chars":19,
 "created_at":"…","sent_at":"…","status_url":"/api/v1/sms/3f1c…","delivery_report":{"status":"requested"}}

  
Other errors return {"ok":false,"error":"…"}:

  

    
StatusMeaning

    
400Invalid number, message too long, bad body or Idempotency-Key, or no message and no default

    
401Missing or invalid API key

    
403The API key does not have the permission this endpoint needs

    
422Idempotency-Key already used for a different message

GET /api/v1/sms/{id}

  
The current status of a message your key sent, with its delivery report when the gateway requests them:
    "delivery_report":{"status":"requested"} until the network reports, then "delivered" (with
    at) or "failed". Not every network sends reports.


  
GET /api/v1/inbox

  
Received SMS, oldest first, for keys given the read inbox permission in the router (it is off for new keys:
    the inbox holds one-time codes). Parameters: after_id (return messages newer than this id),
    since (RFC 3339 time), limit (1–100, default 50). Poll with the last next_after_id:

  
curl "https://sms.example.com/api/v1/inbox?after_id=0" -H "Authorization: Bearer $SMSGW_KEY"

{"ok":true,"messages":[{"id":41,"from":"VM-BANK","text":"Your OTP is 123456","sms_time":"2026-11-26T10:00:00+05:30",
 "received_at":"2026-11-26T10:00:04+05:30"}],"next_after_id":41,"more":false}

  
For push delivery instead of polling, the router can POST each received SMS to a webhook (router web UI, SMS forwarding).


  
GET /api/v1/status

  
Returns modem state, limits, your key's permissions and today's usage for your key.
